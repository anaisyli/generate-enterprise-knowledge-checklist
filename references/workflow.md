# 详细流程与文稿格式

## 参考与迁移

主模板为 `assets\templates\体外诊断仪器与试剂制造行业知识库清单.docx`。模板已去除具体产品型号和文档作者等元数据，蓝字及正文收集要求保留。先读完整文本及蓝色文字，观察七章、段落、要点数量和篇幅；不要把原行业、示例型号、医疗注册要求和文字直接带入新行业。无法读取 DOCX 时，可使用 Python 标准库的 `zipfile` 和 XML 读取 `word/document.xml`；按段落、run 的 `w:color` 分辨蓝字。剩余四份文档作为同行业内容改写风格的参考，不自动作为用户企业的事实。

生成遵循参考模板而不机械套用：1.1 公司背景、公司优势、主营业务与主要产品、认证与资质；1.2 五个能力要点，按新行业适当改名替换原来的诊断专用能力；1.3 发展历程。每个展开的小类四项：产品概述、产品特性、应用场景、产品规格参数。3.1 ODM/OEM；3.2 按参考模板提供五个与实际行业匹配的行业方案，不能确定适用性时用待确认语气；4.1 四类案例，4.2 其他案例；5.1、5.2 各五个趋势要点，改写成请客户提供观点与资料，避免虚构趋势事实；6 七个结合行业的示例问题；7 七类资料。若用户另有明确数量要求优先遵循，无法可靠识别某类时不要虚构事实。各层标题及要点标题附英文，型号本身可直接保留。

总篇幅按约 6000 字为目标，不是机械门槛：以中文字符数量加英文单词数量的近似值估计，不含空白与标点；记录计数和差异。只有很少小类时，保持真实类目和模板数量优先，不能为了达标编造或扩写其他产品。各版块篇幅应大致参照主模板，避免过短空泛。

## 蓝色提示：不得省略

主模板中的蓝字有三个功能。保留在 Word 的对应位置，允许改写，但意图不能减少：

1. 标题之后：`*建议优先提供英文资料，中文资料也可。`
2. 第一大类展开的小类之后：`*其余产品小类请按实际情况继续补充，可参照以上框架提供资料。` 即使小类不超过五个也保留：这是供客户自行补充的提示，不是生成更多正文的指令。
3. 每个其他大类标题之后各一条：`*请根据实际产品类目补充该大类下的产品小类，并参照以上框架提供资料。` 不自动列出小类或撰写产品正文。
4. 5. 行业趋势与未来展望标题之后、5.1 之前：`*此部分可提供已有行业文章、技术文章、白皮书、展会资料、公众号文章、行业报告或内部培训资料。`

提示 1、2、3、4 分别是模板里原蓝色内容的保留及表述调整。蓝字应为 `0000FF`，不是仅凭文本颜色名称；不要将其他正常文字变蓝。

## 官网研究及不确定性

只使用获得授权的、可访问的公开页面和用户提供的资料。先看导航及产品列表，再尽可能查产品详情、公司介绍、解决方案、应用、案例、质量认证、下载页；必要时通过现有浏览器查看动态加载页面。记录每个栏目已访问页面、具体 URL 和访问失败原因，不要宣称“读完全部官网”。产品种类按用户截图/明确指定目录优先，官网补充业务背景，不因推断增加类目；截图不清晰、来源冲突或第一类无可靠小类时需向用户提出具体问题。

官网产品事实用于选择清单范围和英文名，不把推测的行业能力说成企业事实。官网没有 ODM/OEM 时仍保留该节，但用“如适用，请说明是否提供及范围”；对认证、客户案例、工艺、性能、市场等同理，不虚构型号、参数、资质、客户及案例。适用标准或法规只作为按产品与目标市场确认的待提供资料，不能宣称必然适用。行业相关术语应检查含义与上下文，不确定的在内部记录待核实。

## 审核

先自行通读生成稿并修复：行业错配或前一行业残留；英文拼写和行业用语；参数、流程、法规及应用描述的准确性；语病；标题及编号；所有蓝色提示及具体位置；产品分类和来源一致；无公司名、无表格。逐项检查模板主题数量、四项产品内容、五个子类上限及只留其他大类标题。脚本仅校验能机械确认的结构和部分措辞，不保证行业事实、翻译、企业名称遗漏、表述质量或字数达标。出现警告要实际检查，不能把警告当作通过。

单独保留研究记录：企业行业判断、产品中英文名称与来源、已访问/失败网址、待确认项、审核结果、字符数量及蓝色提示检查。不把网址、内部审核说明或客户公司名写入客户版 Word。

## JSON 输入与 Word 导出

创建 UTF-8 JSON（不要用 Markdown 代码围栏）；`paragraphs` 与 Word 顺序一致。每项 `kind` 是 `title`、`heading`、`label`、`text`、`blue` 之一，`text` 是纯文本。`heading` 编号写在文字开头，例如 `2.1.1`；`label` 是双语资料要点标题，不自带编号；纯型号也可用作标题。`product_categories` 是已确认的按顺序排列的实际产品大类，`first_category_subcategories` 是第一个大类的实际小类完整列表（可以超过五个，模型只写前五个）。字符串内容要和 `heading` 后面的名称完全一致，包含中英文，以便机械核验。

示意仅演示输入格式，不是完整合格稿件；必须生成完整七章及各段落后再执行：

```json
{
  "product_categories": ["自动化分拣线 (Sorting Line)", "柔性滚筒输送机 (Flexible Roller Conveyor)"],
  "first_category_subcategories": ["环形交叉带分拣机 (Circular Cross-Belt Sorter)"],
  "paragraphs": [
    {"kind": "title", "text": "智能物流装备行业知识库清单"},
    {"kind": "blue", "text": "*建议优先提供英文资料，中文资料也可。"},
    {"kind": "heading", "text": "1. 公司介绍 (Company Profile)"},
    {"kind": "heading", "text": "1.1 公司简介 (Company Overview)"},
    {"kind": "label", "text": "公司背景 (Company Background)："},
    {"kind": "text", "text": "请介绍公司成立背景、业务定位及主要市场。"}
  ]
}
```

产品大类标题必须严格写作 `2.1 产品大类1：` 后紧接对应目录名称，依次递增；小类必须写作 `2.1.1 ` 后接小类名称。一级标题为 `1. ` 到 `7. `；其他章节小标题使用 `1.1 `、`3.2.1 ` 等。不要写额外 `2.x.y` 或 `2.x.y.z` 标题。

四类蓝字使用上面的精确文本，脚本据此验证位置，不支持另行改写；如需进一步优化文案，应同时更新此文件及脚本常量与测试。

在 Skill 目录执行：

```powershell
python scripts\render_checklist.py ".\稿件.json" ".\行业知识库清单.docx"
```

命令返回 0 才表示机械检查和导出成功；出现结构错误时不创建输出，已存在输出不会覆盖。脚本将提供粗略篇幅警告；不要据此跳过人工审核。文稿是内部中间文件，不作为客户版交付。脚本生成的是无表格 DOCX，标题、正文和蓝色提示按段落分开；若用户指定其他复杂格式，应说明本脚本不会复制全部原模板版式，另用可用文档工具调整后重新检查。
